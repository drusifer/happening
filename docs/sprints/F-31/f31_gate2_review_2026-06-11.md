## Decision-by-Decision UX Review

### D1 — No new controller class ✅
Internal implementation detail. No UX impact.

### D2 — Flutter-only animation; single setSize at boundary ✅
The asymmetry is actually a UX win:
- **Hide**: smooth Flutter contraction → OS window snaps to mini at end. The transparent snap is
  invisible (background is transparent), so user sees a clean slide-to-mini.
- **Show**: OS window snaps to full (invisible, background still transparent) → Flutter runs
  mini→full reveal. User sees content appearing from the left — spatially coherent with ←/→
  mental model.

Both paths deliver a clean perceived animation. Non-blocking concern: the "snap" at hide-end
on Windows may occasionally show a brief frame of OS-native window animation conflicting with
the Flutter animation. Neo should verify on Windows during Phase C UAT (AC-F31-1-4).

### D3 — Strut released BEFORE animation, re-acquired AFTER ✅
Correct. User hides strip → screen space freed immediately, even while animation plays.
This is better than the minimum "before or during" in AC-F31-4-1 — it's "before" consistently.

### D4 — Z-order save/restore for send-to-back ✅
Smith Note C from Gate 1 is fully resolved. The mini widget is always-on-top regardless of
pre-hide STB state. Post-show restore of STB mode satisfies H4 (Consistency) — user returns
to the same interaction mode they had before hiding. No UX concerns.

### D5 — Mini width computed from formula ✅
The `fontSizePx * 6.0` estimate is derived from the existing countdown width calculation at
`timeline_strip.dart:551`. Grounded in real usage. **See Note F** for UAT validation.

### D6 — `onHideStrip`/`onShowStrip` hook naming ✅
Clear, consistent with existing hook naming pattern (`onWindowModeChanged`, `onDisplayChangedExtra`,
`onDispose`). No UX impact (internal API), but good design coherence.

### Settings-close-on-hide (Morpheus addition, not in stories) ✅
The arch closes the settings panel on HIDE (cleaner than AC-F31-3-4 which only requires it
on SHOW). Correct UX call — showing a settings panel on a mini widget is impossible, so
closing it eagerly prevents a confused state where settings were "open but invisible."

## Non-Blocking Notes for Neo

### Note D — `_buildCountdownPositioned` is a `Positioned` — can't go inside a `Row`

The arch's `_buildMiniWidget` snippet uses `_buildCountdownPositioned(...)` inside a `Row`.
But `_buildCountdownPositioned` returns a `Positioned` widget — this will throw a layout error
outside of a Stack.

**Fix:** Extract the inner countdown display content from `_buildCountdownPositioned` into a
shared `_buildCountdownContent` helper (it already exists at line 768 of timeline_strip.dart),
and call that helper directly in the mini widget. Or inline the `StreamBuilder<DateTime>` +
`CountdownDisplay` call without the `Positioned` wrapper. The countdown rendering logic is
already cleanly separated from the positioning.

### Note E — Test the hide-end "snap" on all platforms

On Windows, native window resize may have a brief OS-level animation. If the Flutter
300ms hide animation and the OS snap-to-mini resize produce a visible double-animation,
Neo should move the `wm.setSize(miniSize)` call to BEFORE the Flutter animation starts
(matching the "show" sequence pattern), then clip the Flutter content to the mini width
during animation. Platform-dependent — verify on Windows.

### Note F — Validate mini width formula against longest countdown text

The formula computes enough width for typical countdown strings. Validate against:
- "23 h 59 min" (longest untilNext format)  
- "in 9 h 59 min" (if prefix is included)

If either clips in UAT, add a constant buffer (+16px) to the formula. This is a
one-line fix — flag it during Phase B integration testing, not a gate blocker.
