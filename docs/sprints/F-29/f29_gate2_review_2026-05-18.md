## New Notes (non-blocking)

### Note 5 — geolocator "Use Current Location" — permission UX

**HEURISTIC:** #1 Visibility of System Status + #9 Help Users Recover from Errors
**ISSUE:** If the user denies location permission, the app must communicate clearly *why* the button didn't work and what the user should do. A silent no-op is a usability defect.

**FIX:** When geolocator returns `LocationPermission.denied` or `deniedForever`:
- `denied`: show inline message "Location access denied. Grant permission in System Settings, or enter your location below."
- `deniedForever`: same message; on desktop the user must go to System Settings manually.
This is an implementation concern for Neo during Phase C, not a gate blocker.

### Note 6 — City search UX — what happens if no match found

**HEURISTIC:** #9 Help Users Recognize, Diagnose, and Recover from Errors
**ISSUE:** If the user types a city name that doesn't resolve (typo, small town not in lookup table), the field should not silently accept invalid input.

**FIX:** If city search returns no results, show "No results for '{query}' — try a larger nearby city, or use the Advanced coordinates fields." The field should never save unresolved input.

### Note 7 — MoonPhaseBadge accessibility

**HEURISTIC:** #6 Recognition Rather Than Recall
**ISSUE:** A tiny badge showing "Waning Gibbous 73%" may not be readable at strip scale for all users.

**FIX:** The badge should have a tooltip or hover detail showing the full phase name. On hover (or long-press mobile), expand to "Waning Gibbous Moon — 73% illuminated." Neo to ensure the badge has a `Tooltip` widget wrapping it.
