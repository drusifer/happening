## Coverage Observations (Non-Blocking)

### Observation 1 — `wasJustAutoReturned` is a one-shot edge, not directly tested in Phase A

`DisplayService._refresh` sets `_wasJustAutoReturned = true`, calls `notifyListeners()`, then
resets to `false` synchronously. The semantics are: listeners that synchronously read the
flag during `notifyListeners()` see `true`; subsequent reads see `false`. This is exactly
what the Phase E `DisplayFallbackIndicator` animation needs.

It is not directly tested in Phase A because no consumer exists yet. **Trin will add a
synchronous-read test in F30-E2** when the animation widget is added. No Phase A blocker.

### Observation 2 — `_hasPersistedPreference()` uses runtime type check

`_hasPersistedPreference()` returns `_choiceResolver is! _NullChoiceResolver`. This is a
mildly fragile coupling — if Phase B's composite-fingerprint resolver is constructed with no
persisted choice, it will return true (i.e., the service will think the user has a choice
when they don't, putting it in fallback every session for a fresh install).

Recommendation for Phase B: `DisplayChoiceResolver` should expose `bool get hasPreference`,
and `DisplayService._hasPersistedPreference()` should call that. Trivial refactor.

### Observation 3 — Burst-event test allows up to 3 probe calls

The test `burst of events coalesces` accepts ≤3 probe calls instead of exactly 2. This is a
deliberate tolerance because the debounced refresh loop drains `_refreshPending` and may
yield to the event loop more than once. Real-world coalescence is verified at Phase F UAT
with actual screen_retriever events. Tolerance is appropriate for a unit test.

### Observation 4 — Probe (F30-A2-probe) correctly deferred

The Wayland event-coverage probe cannot run without a real `screen_retriever` subscriber.
Neo correctly deferred it to Phase C2 (WindowService wiring). `DisplayEvents` interface
lets the real subscriber plug in cleanly. No Phase A gap.
